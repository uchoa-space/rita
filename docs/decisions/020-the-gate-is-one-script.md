# ADR 020: The gate is one script — `bin/ci` locally now, the same steps in Actions when a remote exists; there is no CD

- **Status:** Accepted (the remote itself is the author's call — see Consequences)
- **Date:** 2026-08-30
- **Source:** `docs/intent/crew.md`; CI review of ADR 014, 016, 017, 019; `.github/workflows/ci.yml` and `.github/dependabot.yml` as generated by `rails new`; `adr-harvest/spaces/010` (commits on `main` until a remote exists), `spaces/013` (one account: CI required, review not enforceable), `cuy/0008` (a local Forgejo, now down)

## Context

ADR 017 says nothing lands unreviewed and ADR 016 says the boot rules run in the suite, but no
document names the command that means "green". The generated workflow has never run — there is
no remote — and it is wrong for this project: a `postgres` image without pgvector, a system-test
job ADR 016 forbids, `libvips` for a gem ADR 019 removes, and an 87 MB ONNX model fetched from
the Hub on every run. Deploy is out of scope (`docs/intent/rita.md` § 5), so a CD pipeline would
automate nothing.

## Decision

**One script is the gate.** `bin/ci` runs, in order and stopping at the first failure:
`bundle audit`, `bin/importmap audit`, `bin/brakeman --no-pager`, `bin/rubocop`,
`bin/rails db:test:prepare test` (which carries `rita:verify`, `rita:vocabulary`, the contrast
audit and the `errors.domain` check, ADR 016). It prints the ADR behind each step. A review
(ADR 017) names the `bin/ci` run in its Checked section; a change whose `bin/ci` is red is not
reviewed. No step is skipped, silenced or made optional — a red step is fixed or the change
waits.

**The workflow is the script.** `.github/workflows/ci.yml` is rewritten to call `bin/ci` and
nothing else, against `pgvector/pgvector:pg17`, with `~/.cache/informers` cached by model id
(ADR 019) so the embedder never downloads in CI, with no system-test job and no `libvips`. Until
a remote exists the file is inert and `bin/ci` on the author's machine is the whole gate — the
state `spaces/010` recorded and lived with.

**When a remote exists**, `main` requires the `ci` check and forbids force-push and deletion;
no required review, because one account cannot approve its own pull request (`spaces/013`) —
the review stays the ADR 017 discipline, on record in the PR. Dependabot's weekly bundler PRs
are the "one dependency per change" of ADR 017, each gated by the same `bin/ci`.

**No CD.** Nothing deploys. `Publish` writing an MDX file is the only release, its rollback is
`git` in the blog repository, and the blog's own build is its own pipeline (ADR 006, 014).
`kamal` and `thruster` leave with ADR 019; a deploy, should one ever be wanted, is a new ADR.

## Consequences

- "Green" has one meaning and one command, on a laptop and in Actions alike.
- **For the author:** which remote — a public GitHub repository (free CI, the showcase the
  intent asks for, `spaces`' path) or a self-hosted Forgejo (`cuy/0008`, no CI without a runner)
  — is a publishing decision and stays yours. This ADR does not pick.
- Bad: `bin/ci` takes as long as its slowest step; brakeman on a small app is seconds, the
  suite is seconds (`spaces/009` sets the ceiling at which it is split).
- `owed.md` gains `bin/ci` and the workflow rewrite.

### Tension to watch

`bin/ci --fast` that skips audit "for the inner loop", then becomes the only way anyone runs
it. The inner loop is `bin/rails test path/to/one_test.rb`; the gate is the gate.

## Post seed

- **Angle:** a project with twenty decisions about quality and a CI file that had never
  executed — and the fix being a shell script, not a platform.
- **Tension:** the pull to wire GitHub, branch rules and a deploy on day one, against a gate
  that must mean the same thing with no remote at all.
- **Payoff or cost:** unproven — the first red `bin/ci` that stops a change before a review.
